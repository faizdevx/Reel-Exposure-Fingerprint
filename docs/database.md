# Database

PostgreSQL 16 with the `vector` (pgvector) extension. One store for rows, vectors and the job queue. Schema source: spec §9 plus the owner-approved additions in ADR-020 (migration `0001`) and the ADR-004 auth tables (migration `0002`). Implemented in `server/migrations/versions/`, mirrored in `server/app/models.py`. Migrations: Alembic only; never edit an applied migration.

## Tables

| Table | Purpose | Key |
|---|---|---|
| `users` | Dashboard accounts (email, argon2id `password_hash`) | `id` |
| `extension_tokens` | Extension Bearer tokens, stored as `token_sha256`; `revoked_at` for per-device revocation | `id` |
| `consents` | One row per user: `policy_version`, `granted_at`, `revoked_at` | `user_id` |
| `sessions` | Monitoring sessions: `started_at`, `ended_at`, `status`, `stop_reason` | `id` |
| `reel_exposures` | One row per viewing instance. Metadata, `dwell_ms`, `video_duration_ms`, `field_status` (jsonb), `adapter_version`, `process_status` (default `pending`) | `event_id` |
| `content_features` | OCR text and confidence, `text_embedding vector(384)`, `visual_embedding vector(768)`, `modalities[]`. Keyed by user and Reel, not event; one user's rows are never read for another (ADR-024, migration `0006`) | `(user_id, reel_shortcode, pipeline_version)` |
| `topics` | Taxonomy rows: `slug`, `label`, `taxonomy_version`. Source file: `taxonomy/topics.json` (seeding is M3) | `id` |
| `topic_assignments` | Per-user, per-Reel topic distribution: `p_text`, `p_visual`, `p_fused` (ADR-024) | `(user_id, reel_shortcode, pipeline_version, topic_id)` |
| `fingerprint_snapshots` | Topic-weight vectors (`weights` jsonb) per user, `kind` (`exposure` or `engagement`), `bucket` (`session` or `day`) | `id` |
| `topic_transitions` | Counts of topic → next topic per user | `(user_id, from_topic, to_topic)` |
| `prediction_state` | The next-topic prediction and the evaluation summary per user and prediction version (migration 0004) | `(user_id, pipeline_version)` |
| `survey_responses` | How the self-report survey ended: `submitted` or `skipped` (migration 0005) | `user_id` |
| `self_report_ratings` | The user's 1 to 5 interest rating per topic (migration 0005; check `rating BETWEEN 1 AND 5`) | `(user_id, topic_id)` |
| `predictions` | Prequential predictions: `model`, `distribution`, `actual_topic`, `hit_top1`, `hit_top3`, `pipeline_version`, `created_at` | `id` |
| `invites` | Single-use invite codes as SHA-256 (ADR-004). `expires_at`, `used_at`, `used_by` | `code_sha256` |
| `user_sessions` | Dashboard login sessions: SHA-256 of the cookie id, `expires_at` (ADR-004) | `id_sha256` |
| `jobs` | Work queue: `kind`, `payload`, `status` (default `queued`), `attempts`, `run_after`, `last_error`, `created_at` | `id` |

UUID primary keys: `users`, `extension_tokens`, `sessions`, `reel_exposures` (`event_id`, generated by the extension). No server-side UUID default; the application supplies IDs. All timestamps are `timestamptz`.

Indexes: `reel_exposures (user_id, observed_at)`, `reel_exposures (reel_shortcode)`, `fingerprint_snapshots (user_id, kind, taken_at)`, `jobs (status, run_after)`. No vector index until >100k rows; exact search is enough.

## CHECK constraints (ADR-020)

| Constraint | Rule |
|---|---|
| `ck_fingerprint_snapshots_kind` | `kind IN ('exposure', 'engagement')` |
| `ck_fingerprint_snapshots_bucket` | `bucket IN ('session', 'day')` |
| `ck_*_non_negative` | `>= 0` on `dwell_ms`, `video_duration_ms`, `n_reels`, `topic_transitions.n`, `jobs.attempts` |
| `ck_*_unit_interval` | `[0, 1]` on `ocr_confidence`, `p_text`, `p_visual`, `p_fused` |
| `ck_invites_used_pair` | `used_at` and `used_by` are both set or both null |
| `ck_user_sessions_expiry_after_create` | `expires_at > created_at` |
| `ck_sessions_status` | `status IN ('active', 'stopped')` (ADR-014) |
| `ck_sessions_stop_reason` | `stop_reason` null or one of `user`, `left_surface`, `tab_closed`, `time_cap`, `consent_revoked`, `browser_restart` |
| `ck_sessions_state_consistent` | active: no `ended_at`, no reason. stopped: both set |
| `ck_sessions_end_after_start` | `ended_at >= started_at` |
| `ck_consents_revoke_after_grant` | `revoked_at` null or `>= granted_at` |

Partial unique index `uq_sessions_one_active_per_user` on `sessions (user_id) WHERE status = 'active'`: at most one active monitoring session per user (migration `0003`, ADR-021).

NULL passes every check. `sessions.status` and `stop_reason` are constrained (ADR-014). `reel_exposures.process_status` and `jobs.status` are not: the spec does not define them yet.

## Rules

- **Ownership:** every user-scoped table carries `user_id`, or is reachable from one by foreign key. Every query filters by `user_id` taken from the token or cookie.
- **Idempotent ingest:** `event_id` is the primary key; insert `reel_exposures` with `ON CONFLICT (event_id)` so retries never duplicate.
- **No silent defaults:** `field_status` records `available` or `unavailable` for each captured field. Missing values stay null, never filled in.
- **`reel_exposures.field_status` content (ADR-023, Proposed):** `{"reel_shortcode", "observed_at", "creator_handle", "caption", "hashtags", "video_duration_ms"}` each `available` or `unavailable`, plus `"caption_truncated": bool` and `"frame_count": int`, two facts the event carries that spec §9 has no column for. A new migration would be needed to move them into columns.
- **Jobs from ingest:** one `jobs` row with `kind = 'exposure'` and `payload = {"event_id": "..."}` per newly stored event, written in the ingest transaction. No content in the payload.
- **Versioning (N9):** `pipeline_version` is `NOT NULL` on `content_features`, `topic_assignments`, `fingerprint_snapshots` and `predictions`. See Open issues for the planned split.
- **Raw media:** never stored in Postgres. Only embeddings and text. Frames live on the frame volume (see `docs/privacy.md`).
- **Job queue:** workers claim jobs with `SELECT … FOR UPDATE SKIP LOCKED` and retry with backoff through `run_after`. `last_error` holds error classes and IDs only, never user content.
- **Reproducibility:** snapshots must be rebuildable from stored assignments.
- **Embedding width:** `visual_embedding vector(768)` is provisional until M0 picks the SigLIP variant. Changing it needs a new migration.
- **Topics first:** a `topics` row must exist before a transition, prediction or assignment references it, including `other`.

## Deletion

Session delete and delete-all must leave zero rows and zero files, verified by a count query over every table.

- Deleting a user cascades to every user-scoped table.
- Deleting a session cascades to its exposures, its session snapshots, and the predictions made before its events.
- Not covered by cascades: `topic_transitions` counts (need the ADR-012 rebuild) and `jobs` payloads. The Reel cache is per user (ADR-024) and cascades with the user; a session delete removes the user's cache rows for Reels that none of their remaining exposures refers to.

## Tests

`tests/test_database.py` (needs `TEST_DATABASE_URL`):

- **Session rules (ADR-014, 0003):** every stop reason accepted; unknown status or reason, inconsistent active/stopped states and end-before-start rejected; one active session per user, but a new one after the old stops, and one per user across users; consent revocation cannot precede its grant.
- **Schema matches:** exact table set; models vs migration via Alembic autogenerate; exact foreign keys with delete rules; exact CHECK constraint names; vector widths; UUID and composite primary keys; indexes; `NOT NULL` pipeline versions.
- **Behaviour:**
  - defaults;
  - `event_id` idempotency;
  - unique email and token;
  - each CHECK constraint rejects bad values and accepts bounds and NULL;
  - unknown topics rejected;
  - a referenced topic cannot be deleted;
  - session and user cascades leave other users' rows intact;
  - downgrade/upgrade round trip.
